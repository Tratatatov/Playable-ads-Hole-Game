# 🎮 Rules: 3D Playable Ad Development (Cocos Creator / Three.js / WebGL)

Этот документ содержит свод обязательных правил и инструкций для Antigravity при работе с кодом и архитектурой данного Playable Ad проекта.

---

## 1. 🏗️ Архитектура и Структура Кода

1. **Event-Driven Architecture (Pub/Sub):**
   * Все взаимодействия между системами (Physics, UI, Audio, GameLogic) ДОЛЖНЫ проходить через единую шину событий `EventBus`.
   * Избегать прямых жестких связей (hard dependencies) между UI и физическими компонентами.

2. **Конечный Автомат Состояний (FSM):**
   * Жизненный цикл игры строго инкапсулирован в `GameStateMachine`.
   * Допустимые состояния: `BootState` -> `TutorialState` -> `GameplayState` -> `EndCardState`.
   * Запрещены хаотичные глобальные флаги состояния вроде `isStarted`, `isOver`, `isWin` вне класса `GameStore`.

3. **Слой Адаптера Рекламных Сетей (Ad SDK Abstraction):**
   * Любые редиректы в стор и сигналы готовности игры ДОЛЖНЫ вызоваться только через абстракцию `AdNetworkManager` (`AdNetworkManager.handleClickout()`, `AdNetworkManager.gameReady()`).
   * Запрещено напрямую использовать вызовы `mraid.open()` или API конкретных сетей в компонентах игры.

4. **Bootstrapper и Инициализация:**
   * У нас есть Bootstrap класс, в котором мы делаем инициализацию сервисов и всех необходимых компонентов со сцены.
   * Компоненты сцены не должны использовать стандартные методы жизненного цикла (`onLoad`, `start` и т.д.). Вместо этого они имеют метод инициализации, который вызывается Bootstrapper-ом.
   * Если класс не подразумевает присутствия на сцене (например, сервис), мы используем обычный TypeScript класс, а не Component (не наследуемся от `cc.Component`).

5. **Реализация интерфейса (UI) через MVP (Model-View-Presenter):**
   * UI компоненты должны реализовываться с использованием паттерна MVP.
   * `View` отвечает только за отображение, ссылки на элементы сцены (например, `Label`) передаются через `LevelConfig`.
   * `Presenter` подписывается на события `EventBus`, получает данные из `GameStore` и обновляет `View`.
   * Классы View и Presenter являются обычными TypeScript классами (не наследуются от `cc.Component`) и инициализируются в Bootstrapper.

---

## 2. ⚡ Производительность и Zero-GC (Garbage Collection)

1. **Запрет выделения памяти в кадре (No Allocations in `update` Loop):**
   * СТРОГО ЗАПРЕЩЕНО создавать новые объекты (`new Vector3()`, `new Color()`, `{}`) внутри функций обновления `update(dt)` или обработчиков 60 FPS.
   * Все временные векторы, матрицы и вычисления ДОЛЖНЫ переиспользоваться из предварительно выделенных переменных (Scratch variables).

2. **Обязательный Object Pooling:**
   * Все повторяющиеся 3D-объекты (макаруны, сладости, визуальные эффекты) ДОЛЖНЫ предварительно создаваться (prewarm) в `ObjectPool` на этапе `BootState`.
   * Запрещено вызывать `instantiate()` / `new Mesh()` или `destroy()` / `remove()` во время активного геймплея. При падении в дыру объект скрывается и возвращается в пул (`pool.release(item)`).

3. **Ограничения ресурсов (Bundle Size Budget):**
   * Общий вес итогового скомпилированного Single HTML билда не должен превышать **3 МБ**.
   * Текстуры: размер не более 512x512, сжатые PNG/JPG или Procedural Materials.
   * 3D-модели: Low-poly геометрия.

---

## 3. 🎨 UI/UX & Responsive Layout

1. **Мгновенный отклик (First Touch Responsiveness):**
   * Первый `pointerdown` игрока должен мгновенно скрывать туториал (`TutorialState` -> `GameplayState`) и активировать взаимодействие.
2. **Адаптивность (Portrait & Landscape):**
   * UI элемент должен динамически пересчитывать позиции и масштабы при изменении ориентации экрана (`window.onresize`).
3. **Обязательный CTA (Call To Action):**
   * Кнопка установки ("Install Now") должна быть всегда доступна и кликабельна в состоянии `EndCardState`.

---

## 4. ⚙️ Инструкции по написанию кода для Antigravity

1. **Типизация:**
   * Строгий TypeScript (`strict: true`). Использование `any` запрещено. Все события в `EventBus` должны быть строго типизированы через enums или интерфейсы.
2. **Сохранение сигнатур:**
   * Не менять сигнатуры публичных методов без явного обновления всех мест их вызова.
3. **Проверка после изменений:**
   * После каждого редактирования кода Antigravity ОБЯЗАН запустить команду сборки (`npm run build` или бандлер) для проверки отсутствия ошибок компиляции TypeScript и целостности итогового Single HTML файлового бандла.

---

## 5. 📦 Префабы и Конфигурация

1. **Обязательное использование Prefab для всех спавнящихся объектов:**
   * Любой игровой объект, который создаётся динамически (коллектаблы, эффекты, снаряды и т.д.), ОБЯЗАН быть реализован как Prefab в Cocos Creator.
   * Процедурное создание нод (`new Node()`, `addComponent()` внутри кода) — запрещено для объектов, которые должен настраивать дизайнер.
   * Prefab передаётся в компонент через `@property(Prefab)` и инстанциируется через `instantiate(prefab)` только на этапе `BootState` (prewarm пула).
   * Запрещено вызывать `instantiate()` во время активного геймплея (`GameplayState`).

2. **Все настраиваемые параметры — в `LevelConfig.ts`:**
   * Любые числовые константы (скорости, масштабы, пороги, таймеры), которые дизайнер может захотеть изменить, ДОЛЖНЫ быть вынесены в `LevelConfig.ts`.
   * Запрещено хардкодить игровые параметры внутри компонентов.


## 6. Editor Tools (инструменты редактора)

1. Все скрипты-инструменты ОБЯЗАНЫ иметь суффикс `Tool` в названии класса и файла (например, `GridSpawnerTool`, `CollectableCounterTool`).
2. **Изоляция от основного кода:** Tools НЕ участвуют в основном игровом коде и должны быть строго изолированы.
   * ЗАПРЕЩЕНО импортировать / вызывать Tool-классы из `GameBootstrap`, сервисов, gameplay, UI presenters и любого runtime-кода.
   * Tools НЕ должны подписываться на `EventBus`, мутировать `GameStore` или управлять FSM.
   * Tools МОГУТ импортировать gameplay-типы (`Collectable`, `CollectableType` и т.п.) только для настройки объектов сцены в редакторе.
   * Основной код НЕ зависит от tools: результаты (счётчики и т.д.) попадают в конфиги вроде `LevelConfig`, а не через live-ссылки на tool.
3. Tools НЕ должны работать во время игры — в `onLoad` обязательно: `if (!EDITOR) { this.destroy(); return; }`.
4. Главный функционал инструмента всегда активируется через кнопку в инспекторе Cocos (get/set свойство с проверкой `if (v && EDITOR)`).
